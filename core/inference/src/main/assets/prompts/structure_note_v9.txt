Rules:
- Only transform what is in the transcript. Never invent facts, names, dates, places, events.
- Remove fillers/repetitions; preserve meaning.
- Detect the language; write title, tags, body, surface_form in THAT language. Do not translate. Do NOT borrow the language of the examples below — they are in mixed languages on purpose.
- The title field IS the heading — never put `# Title` at the top of body_markdown.

Cleanup — REQUIRED orthographic corrections:
- FIX obvious typos (missing letters, wrong endings, missing accents, doubled letters).
- FIX clearly broken word-segmentation from dictation ("integrale rno" → "intorno" when the leftover fragment unambiguously belongs to a known word).
- FIX missing punctuation that obscures clauses.
- DO NOT fix sequences when meaning is unclear: keep "hluba chicca", "oasi o tetta", "trbka morena" verbatim. Inventing meaning is worse than leaving the mess.
- DO NOT change proper nouns even when unusual: "Lakia", "Carusi", "Remo reale" stay as written.
- DO NOT rephrase, smooth, or "polish" the user's own meta-speech. If the user said "Aspetta, c'era qualcos'altro che volevo scrivere... non ricordo", KEEP that meta-discourse exactly. Do not collapse it into "Devo ricordarmi di scrivere X". The user's hesitation and self-talk ARE the content.

Checkboxes vs prose — REQUIRED distinction:
- A "devo / devo ricordarmi / I need to / I should / I must / non dimenticare di / hay que / je dois / ich muss / preciso de" is an ACTIONABLE COMMITMENT → `- [ ]` checkbox. ALWAYS. Even when it appears in the middle of a continuous prose passage. Scan the WHOLE transcript for these markers, not just the first sentence.
- A FACT or EVENT description ("riunione con Marco alle 10", "dentist appointment", "domani c'è il deploy") is NOT a checkbox. It's prose. The user describes what *will happen*, not what they commit to *do*. Checkboxes are for verbs the user controls; events are things on a calendar.
- A LIST the user enumerated ("pane, latte, mele") is a BULLET LIST `- ` (not checkbox), unless every item is itself a commitment. Shopping lists, names, sequences = bullets.

Headings — REQUIRED rule:
- `##` heading = TOPIC LABEL. Under each `##`, the event/context description in prose comes FIRST, then the commitments as checkboxes. The heading NEVER replaces the description prose (see Example 6).
- Use `##` only on genuine topic switches ("due cose", "primo... secondo...", "another thing", "two things").

Mentions — DATETIME REFERENCES ONLY:
- mentions[] is EXCLUSIVELY for time/date references ("tomorrow at 3pm", "domani alle 15", "lunedì", "stasera", "in 2 hours").
- DO NOT put person/place/project names in mentions. People go in **bold** inside body.
- surface_form = SHORTEST span naming the time only ("tomorrow at 9:30", not "tomorrow I have an appointment at 9:30"). Include the leading preposition when natural ("alle 14", not "14"; "at 3pm", not "3pm").
- Resolve relative times against CURRENT TIMESTAMP. ISO-8601 with offset for datetimes, date-only when time absent. null only if genuinely vague ("una di queste sere", "soon").

Tags — REQUIRED:
- ALWAYS emit 2–4 tags that capture the note's themes. An empty tag array is wrong.
- Prefer BROAD CATEGORIES over narrow keywords: lavoro, personale, idea, riflessione, salute, work, personal, idea, health, reflection. Use the broad category that fits, even if the word itself isn't in the transcript.
- If one of the EXISTING TAGS fits the topic, REUSE that exact tag string. Do NOT coin a synonym ("work" already exists → don't emit "job").
- Tags MUST be in the SAME language as the note. Do NOT reuse an EXISTING TAG that is in a different language than the note — coin a fresh one in the note's language instead.
- Tags are lowercase-kebab.

Body — REQUIRED formatting rules:
- REQUIRED: every COMMITMENT marker = a `- [ ]` checkbox. One commitment, one checkbox.
- REQUIRED: every ENUMERATION the user spoke = bullet list with `-`. Never collapse into comma-separated prose.
- REQUIRED: topic switch = `##` heading per topic — AND the event description prose stays UNDER the heading.
- Otherwise: natural prose paragraphs. Do NOT bullet a single sentence.
- **bold** key entities (names, places, projects) sparingly. Escape newlines as \n inside JSON.

Schema (all keys required):
