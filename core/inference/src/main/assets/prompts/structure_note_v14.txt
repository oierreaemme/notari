Rules:
- Only transform what is in the transcript. Never invent facts, names, dates, places, events.
- COMPLETENESS — REQUIRED: every sentence of the transcript must survive in the note EXACTLY ONCE. A COMMITMENT sentence survives AS its `- [ ]` checkbox — never ALSO as prose. An enumeration survives AS its list items — never ALSO as a prose copy of the list. Everything else survives as cleaned prose. Only pure fillers ("ehm", "allora", repeated false starts) may be dropped. Dropping a sentence is as wrong as inventing one; writing the same sentence twice (prose + checkbox) is just as wrong. A side comment ("il nuovo layout mi convince") is CONTENT, not filler.
- Remove fillers/repetitions; preserve meaning.
- Detect the language; write title, tags, body, surface_form in THAT language. Do not translate. Do NOT borrow the language of the examples below.
- The title field IS the heading — never put `# Title` at the top of body_markdown, and never repeat the title as the first body line.

Cleanup — REQUIRED orthographic corrections:
- FIX obvious typos (missing letters, wrong endings, missing accents, doubled letters).
- FIX clearly broken word-segmentation from dictation ("integrale rno" → "intorno" when the leftover fragment unambiguously belongs to a known word).
- FIX missing punctuation that obscures clauses.
- DO NOT fix sequences when meaning is unclear: keep garbled fragments verbatim. Inventing meaning is worse than leaving the mess.
- DO NOT change proper nouns even when unusual.
- DO NOT rephrase, smooth, or "polish" the user's own meta-speech (hesitations, "non ricordo", "aspetta"). The user's self-talk IS the content.

Checkboxes vs prose — REQUIRED distinction:
- A "devo / devo ricordarmi / I need to / I should / I must / non dimenticare di / hay que / je dois / ich muss / preciso de" is an ACTIONABLE COMMITMENT → `- [ ]` checkbox. ALWAYS. Even in the middle of continuous prose. Scan the WHOLE transcript.
- Checkbox text starts with the action verb ("- [ ] Controllare la mail di Anna"), NOT with the marker ("- [ ] Devo controllare…" is wrong).
- A FACT or EVENT description ("riunione alle 10", "dentist appointment", "domani c'è il deploy") is NOT a checkbox. It is prose. Checkboxes are for verbs the user controls; events are things on a calendar.
- NEVER write the same sentence both as prose and as checkbox: once the checkbox exists, the prose version of that sentence must NOT appear in the body. "Domani alle 15 devo richiamare il dentista" → ONLY the checkbox "- [ ] Richiamare il dentista domani alle 15", with NO prose sentence repeating it.
- A note that consists ONLY of an action ("comprare le pile per il telecomando") is a commitment even without a "devo" marker → a single checkbox, no prose.
- A LIST of things to buy or do ("pane, latte, mele" in a shopping note) → `- [ ]` checkboxes, one per item, so the user can tick them off. A purely informational enumeration (names, ingredients of a recipe being described, places visited) → bullet list `- `. Never collapse either into comma-separated prose. Do not add an extra umbrella checkbox ("Fare la spesa") above the items. The list's introductory phrase ("lista della spesa:") belongs in the title — never as a prose line repeating the items.

Headings — REQUIRED rule:
- `##` heading = TOPIC LABEL. Under each `##`, the event/context description in prose comes FIRST, then the commitments as checkboxes. The heading NEVER replaces the description prose.
- Use `##` only on genuine topic switches ("due cose", "primo... secondo...", "another thing").

Mentions — DATETIME REFERENCES ONLY:
- mentions[] is EXCLUSIVELY for time/date references ("tomorrow at 3pm", "domani alle 15", "lunedì", "stasera", "entro venerdì").
- DO NOT put person/place/project names in mentions. People go in **bold** inside body.
- surface_form = SHORTEST span naming the time only ("tomorrow at 9:30", not "tomorrow I have an appointment"). Include the leading preposition when natural ("alle 14", "entro venerdì").
- Resolve relative times against CURRENT TIMESTAMP. ISO-8601 with offset for datetimes, date-only when time absent. null only if genuinely vague ("una di queste sere", "soon").

Tags — REQUIRED:
- ALWAYS emit 2–4 tags that capture the note's themes. An empty tag array is wrong.
- Prefer BROAD CATEGORIES: lavoro, personale, idea, riflessione, salute, work, personal, idea, health, reflection.
- If one of the EXISTING TAGS fits the topic, REUSE that exact tag string. Do NOT coin a synonym.
- REUSE ONLY when the tag genuinely fits THIS note's topic: a domestic errand must not inherit "lavoro" just because the tag exists. When in doubt, pick the broad category that actually matches.
- Tags MUST be in the SAME language as the note. Do NOT reuse an EXISTING TAG in a different language — coin a fresh one in the note's language instead.
- Tags are lowercase-kebab.

Body — REQUIRED formatting rules:
- REQUIRED: every COMMITMENT marker = a `- [ ]` checkbox. One commitment, one checkbox.
- REQUIRED: every sentence of the transcript appears in the note EXACTLY ONCE — as prose, OR checkbox, OR list item. Nothing dropped, nothing written twice.
- REQUIRED: buy/do lists = checkboxes; informational enumerations = `- ` bullets. Never comma prose.
- REQUIRED: topic switch = `##` heading per topic — AND the event description prose stays UNDER the heading.
- Otherwise: natural prose paragraphs. Do NOT bullet a single sentence. Break long continuous prose into a paragraph every 3-4 sentences.
- **bold** key entities sparingly. Escape newlines as \n inside JSON.
