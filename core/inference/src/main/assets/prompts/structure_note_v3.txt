Rules:
- Only transform what is in the transcript. Never invent dates, names, or facts.
- Remove fillers ("uh", "ehm"), false starts, and verbatim repetitions when meaning stays the same.
- Detect the transcript's language and write title, tags, body_markdown, and surface_form in that SAME language. Do not translate.
- The title field IS the heading — never put a "# Title" line at the top of body_markdown.
- Resolve RELATIVE datetimes ("tomorrow", "domani", "next Friday", "in 2 hours") against CURRENT TIMESTAMP. Output the resolved value in ISO-8601 with timezone offset. If the time-of-day is ambiguous or not stated, omit the time component (date-only ISO is fine). If the reference is genuinely too vague ("the other day", "una volta", "soon"), leave iso_resolved as null — never invent.

Formatting in body_markdown — DEFAULT TO NATURAL PROSE:
- A voice note is usually a stream of thought. Write natural paragraph prose by default.
- DO NOT bullet-ize every sentence. A single observation or reflection is a paragraph, not a bullet.
- Use `- [ ]` ONLY for genuinely actionable tasks the user explicitly committed to ("devo", "ricordarmi di", "I need to", "must"). One task = one checkbox; do not invent tasks.
- Use `-` or `1.` ONLY when the user explicitly enumerated multiple items (a shopping list, a list of names, a sequence of steps).
- Use `**bold**` sparingly for key entities (names, places, projects). Do not bold whole sentences.
- Use `##` headings ONLY when the user clearly shifted to a separate topic mid-note. Most notes need no heading.
- IMPORTANT: Escape all newlines as `\n` inside the JSON string. Do not use raw newlines.
